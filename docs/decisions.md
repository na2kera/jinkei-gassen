# 陣形合戦 — 決定事項

2026-11-16 の聞き取り（Q1〜Q24）で合意した内容。ゲームの中身はこの文書が正で、「どう作るか」は `design.md` に書く。
ここにない細部で、作る側が仮に決めたものは `assumptions.md` に書く。

## 1. どんなゲームか

- 古代中国風の戦場で、部隊を並べて陣形を組み、敵とぶつける戦術シミュレーション。
- 漫画「キングダム」の陣形から着想したが、作品の名前・人物・固有の設定・絵柄は使わない。世界観と将は自作する。
- 鶴翼・魚鱗・鋒矢・方円などの陣形名は、兵法の一般の用語なので使う。
- 名前は「陣形合戦」。リポジトリは `~/dev/vite/jinkei-gassen`。

## 2. 遊びの骨組み

| 項目 | 決定 |
|---|---|
| 配置 | マス目に吸い付く。1マスに1部隊。部隊の中に小さな兵が並んで見える |
| 戦闘 | 配置が終わると自動で進む。動きはなめらか |
| 介入 | 戦闘中に号令を出せる（§7） |
| 遊ぶ場所 | PC のブラウザを基準に作り、スマホでも遊べるようにする |
| モード | 1人用のステージクリア型と、友達との1対1オンライン対戦 |

## 3. 見た目

- ドット絵。小さな兵が部隊ごとに並んで動き、ぶつかる。部隊は色と旗で見分ける。
- 視点は、配置中は真上からの見下ろしに固定する。
- 戦闘中は「真上」と「斜め見下ろし」を切り替えられるようにする。ただし先に真上だけで完成させ、斜めはあとから足す。そのために、戦闘の計算と描画を分けて作る。
- 画面の作りは、超富豪で合意した好みに合わせる：ドット調（平らな塗り、2ドット単位の枠、ドット文字）、表示する情報は最小限、グラデーション・ぼかした影・光彩・角丸は使わない。

## 4. 兵種と将

| 兵種 | 役割 |
|---|---|
| 歩兵 | 攻守のバランス型。数の主力 |
| 盾兵 | 足が遅いが、正面からの攻撃に強い。受け止め役 |
| 騎兵 | 足が速い。側面や背後を突くと強いが、正面の盾兵には弱い |
| 弓兵 | 離れて攻撃できるが、接近されると脆い |

- 各軍に総大将の本陣を1部隊置く。**本陣が討たれたら、その時点で負け**。
- 本陣は周囲の味方の士気を上げる。前に出すほど危険になる。
- 個性のある将を部隊に配属する仕組みは、あとから足せる作りにしておく。

## 5. 戦場と配置

- 自軍が部隊を置ける範囲は、**横12 × 奥行き6 を標準**とする（一旦の決定。遊んで合わなければ見直す）。
- 戦場全体は、自軍の配置エリア・中間地帯・敵軍の配置エリアが縦に並ぶ。
- ステージごとに広さを変えられる作りにする。対戦は標準の広さに固定する。
- 置ける部隊の決め方：
  - ステージは手持ちが決まっていて、並べ方だけを考える。
  - 対戦は、兵種ごとの値段と予算があり、その中で自由に編成する。
  - どちらも、本陣を含めて15部隊前後を目安にする。
- 地形は4種。マスごとの性質として作る。対戦用の戦場は左右対称の地形だけを使う。

| 地形 | 効果 |
|---|---|
| 丘 | 上にいる側が有利。弓が遠くまで届く |
| 森 | 騎兵の足が止まり、弓が当たりにくい |
| 川 | 渡っている間は足が遅く、攻撃に弱い |
| 柵・城壁 | 守る側が正面から崩されにくい。攻城・防衛のステージ用 |

## 6. 陣形と戦闘ルール

### 陣形

- **陣形の名前による効果は付けない**。強さは位置関係の共通の決まりだけで決まる：側面や背後から攻められると弱い、隣に味方がいると崩れにくい、囲まれると士気が落ちる、など。
- 並べ方が有名な型に近いと、陣形名（「鶴翼の陣」など）を表示する。表示だけで、効果はない。
- 配置のとき、ひな形（鶴翼・魚鱗・鋒矢・方円など）を選ぶと、手持ちの部隊がその形に自動で並ぶ。そこから手で直せる。ゼロから置くこともできる。
- 自分の配置に名前を付けて保存し、呼び出せる。

### 部隊の方針

配置のときに、部隊ごとに次の4つから1つを選ぶ。相手からは見えない。

| 方針 | 動き |
|---|---|
| 前進 | 正面の敵へまっすぐ進む |
| 守備 | その場を動かず、来た敵を受け止める |
| 迂回 | 外側から回り込み、敵の側面や背後を狙う |
| 本陣狙い | 途中の敵をなるべく避けて、敵の本陣へ向かう |

- 兵種ごとに初期設定を付ける（盾兵は守備、騎兵は迂回など）。ひな形を選ぶと方針も一緒に入る。

### 士気と敗走

- 部隊は兵数と士気を持つ。士気が尽きると、兵が残っていても敗走して戦場から消える。
- 士気が下がる：側面や背後から攻められた、囲まれた、隣の味方が敗走した、兵が大きく減った。
- 士気が保たれる・上がる：隣に味方がいる、本陣が近い、敵を敗走させた。
- 隣がつられて崩れる「総崩れ」が起きることを狙う。

### 勝敗と1戦の長さ

- 本陣を討つと勝ち。
- 本陣以外の部隊がすべて敗走・全滅した側は、その時点で負け。
- 1戦は最長3分。2倍速の早送りを付ける。
- 時間切れ：対戦は、残った兵力の割合が多いほうの勝ち。同じなら引き分け。ステージは面ごとに決める（ふつうの面は負け、防衛の面は守り切れば勝ち）。
- 膠着：だれも攻撃せず、だれも動こうとしないまま10秒たったら、3分を待たずにそこで終える（味方に引っかかって進めないだけの部隊は、動こうとしているので数えない。号令が効いているあいだと、面の敵の予定された号令が残っているあいだも数えない。細かい決まりは `design.md` §3.6.4）。勝ち負けは時間切れと同じ決め方（2026-11-17 にユーザーが決めた。守備どうしが向き合って、時間切れまで待つだけの戦いをなくすため）。
- ステージ独自の勝利条件（「敵の砦の門を破れ」など）も作れるようにする。

## 7. 号令

- 相手は、全軍・左翼・中央・右翼から選ぶ。配置した横位置で、部隊が自動的に左翼・中央・右翼に分かれる。
- 操作は「相手を選ぶ → 号令を選ぶ」の2回押すだけ。
- 種類は3つ。

| 号令 | 効果 |
|---|---|
| 突撃 | 方針を捨てて正面の敵へ突っ込む。しばらく攻撃力が上がり、守りが下がる |
| 堅守 | その場で止まって守りを固める。しばらく守りが上がり、士気が少し戻る |
| 後退 | 自陣側へ下がる。下がっている間は背中を見せるので、追われると危険 |

- 1戦に合計3回まで。
- 突撃と堅守の効果は10秒ほど続き、切れたら元の方針に戻る。
- 出した号令は相手にも見える（「敵右翼、突撃」の表示と、太鼓や旗の演出）。
- 効果の長さや強さの数字は、遊びながら調整する。

## 8. ステージ（1人用）

- 敵の配置（どこに何の兵種がいるか）は配置中に見せる。敵の方針は見せない。
- 面によって「霧で敵の一部が見えない」などの変化を付けられる作りにする。
- 全部で15面ほど、3章。
  - 第1章 平原（5面）：遊び方を覚える。歩兵だけ → 盾兵 → 弓兵 → 騎兵と方針 → 号令を使う決戦。説明文を読ませず、面を解くと覚える作りにする。
  - 第2章 地形（5面）：丘の取り合い、森の待ち伏せ、川を渡る戦い、谷の狭い道、兵力で劣る戦い。
  - 第3章 攻城と防衛（5面）：柵を守り切る、砦を攻める、挟み撃ちにされる、少数で時間を稼ぐ、最後の大決戦。
- 前の面を勝つと次の面が開く。
- 対戦は、第1章を終えると開く。（2026-11-20 にやめた。初めから押せる。§19）
- 面は「地形・敵の配置と方針・手持ちの部隊・勝利条件」を書いたデータとして作る。
- 評価は星3つ：勝てば1つ、自軍の兵が半分以上残れば2つ、7割以上で3つ。
  - 最初は「8割以上で3つ」としたが、第1章の 1-2・1-3・1-4 では、約1000通りの配置を試しても8割に届かなかった（最良で 78%・77%・72%）。2026-11-17 に7割へ下げた。
- 戦闘後に、簡単な振り返り（部隊ごとの戦果、どこが崩れたか）を表示する。

## 9. 対戦（友達と1対1）

1. 1人が部屋を作ると4桁のコードが出る。もう1人がコードを入れて入室する。
2. 対戦用の戦場（平原、中央に丘、中央に川、両脇に森など。どれも左右対称）から、毎回ランダムに1つ選ばれる。
3. 編成と配置は120秒。お互い相手が見えない。ひな形や保存した陣形を使える。2人とも「完了」を押せば、時間を待たずに進む。時間切れなら、その時点の配置で始まる。
4. 両軍の配置が同時に公開され、数秒の間を置いて戦闘が始まる（最長3分）。
5. 勝敗と振り返りを表示する。両者が「もう一戦」を押すと、同じ部屋のまま2に戻る。

- 1戦ごとに決着し、部屋にいる間の通算成績（例：2勝1敗）を表示する。何戦やるかは自由。
- 通信が切れても戦闘は止めない。切れた側の部隊は方針どおりに戦い続け、号令だけが出せない。同じ部屋に戻れば、その時点の戦況から続きを見て、号令も出せる。
- 配置中に切れた場合は、制限時間が来た時点の配置で始まる。
- 片方が60秒いない状態で1戦が終わったら、部屋は待機に戻り、残った人に「相手を待っています」と表示する。
- 戦闘の計算は、サーバー側で1つだけ行う。

## 10. 保存

- アカウントは作らない。
- ステージのクリア状況、星の数、保存した陣形、対戦で使う名前は、その端末のブラウザに保存する。
- 対戦の途中で切れても、端末に保存した識別用の番号で同じ部屋に戻れる。
- サーバーへの保存（記録の引き継ぎ、通算成績）は、あとから足せる。

## 11. 技術

| 部分 | 使うもの |
|---|---|
| 画面と描画 | Phaser + TypeScript + Vite |
| 戦闘の計算 | 素の TypeScript + Vitest。画面から切り離し、1人用はブラウザで、対戦はサーバーで同じものを動かす |
| 対戦サーバー | Cloudflare Workers + Durable Objects（1部屋 = 1 Durable Object、WebSocket） |
| 公開 | Cloudflare Workers |
| 構成 | pnpm のモノレポ（engine / server / client） |

- React は使わない。メニューや部屋のコード入力は、Phaser と素の HTML で作る。
- バージョンは `design.md` に固定して書く。変えるときは相談する。

## 12. 作る順番

段階ごとに動かして確かめてから、次へ進む。

1. **戦闘の土台**：平原1面。4兵種と本陣、マス目への配置、方針、自動戦闘、士気と敗走、号令3種、勝敗の判定。絵は仮のもの。
2. **1人用の最初の形**：第1章の5面、ひな形、陣形名の表示、星の評価と振り返り、ドット絵の兵と戦場、音。
3. **対戦**：サーバー、部屋とコード、予算での編成、120秒の配置、同時公開、号令のやり取り、切断と復帰。戦場は平原だけ。
4. **地形と残りのステージ**：丘・森・川・柵と城壁、第2章と第3章の10面、対戦用の地形つき戦場。
5. **仕上げの追加**：自分の陣形の保存、斜め見下ろし視点。

## 13. あとから足す候補

決めていないが、足せる余地を残しておくもの。

- 地形：沼、崖、橋、火計の草原
- 兵種：戦車、弩兵、軽騎兵
- 個性のある将を部隊に配属する
- 疲労（走り続けたり戦い続けたりすると弱くなる）
- 面ごとの課題（「号令を使わずに勝つ」など）
- 協力プレイ（2人で1つの軍）
- キャンペーン型（部隊が育つ、損害を持ち越す）
- 自由モード（地形・敵陣形・兵数を選んで試す）
- 先に2勝で決着する形式
- サーバーへの保存とアカウント

## 14. 視点を増やす（issue #1。2026-11-18 に決定）

- 戦闘の画面の視点を、真上・斜めに加えて2つ増やす。
- **横から**：戦場の横の辺から、少し見下ろす。自軍が画面の左、敵軍が右。遠近はつけない。
  - 両軍のあいだの向き（奥行き）を 0.75 倍に縮めて、いまの戦場の枠（横 288px）に収める。兵の絵は縮めない。画面の配置（ボタンや文字の位置）は変えない。
- **将軍**：自分の本陣の位置から、低い高さで敵の方向を見る。視点は固定（本陣は動かない）。
  - 遠近をつける。兵の絵は、手前 3 倍・中ほど 2 倍・奥 1 倍の3段階（ドットを崩さないよう、整数倍だけ）。
  - 3 倍の兵と「戦場ぜんぶを枠に入れる」は両立しないので、**手前を切る**（2026-11-19 に決定）。手前は本陣のまわり 4 列ぶんだけが枠に入り、奥は 12 列ぜんぶが入る。枠の外の部隊は見えない（号令は効く）。
  - 地平線より上に、空と遠景のドット絵を出す。絵は Codex が作る。1人用の15面に1枚ずつ、対戦の地図にも1枚ずつ。色は、いまの戦場の絵に揃える。
- 4つの視点すべてで、同じ操作が使える（部隊を押して兵数と士気を見る、号令）。
- 切り替えは、いまの「視点」ボタン1つ。押すたびに 真上 → 斜め → 横から → 将軍 → 真上。選んだ視点は端末に保存する。
- 使えるのは戦闘の画面だけ（配置・公開・結果は真上のまま）。1人用と対戦の両方。視点で見える情報は増えない。

## 15. 遊軍（秘密部隊。issue #2。2026-11-18 に決定）

- **遊軍**：手持ちの部隊（本陣以外）から1つを選んで、戦場に置かずに控えさせる。控えさせなくてもよい。総兵力は変わらない。兵種は自由。方針は、ふつうの部隊と同じように決める。
- **呼ぶ**：開戦から 5 秒たったあとなら、1戦に1回だけ、いつでも呼べる。左か右を選ぶ。呼ぶとすぐ、戦場の中央の線のすぐ自陣側の、選んだ側の端のマスに現れる。そこに部隊がいれば、いちばん近い空いている端のマスに現れる。現れたあとは、ふつうの部隊と同じ決まりで戦う。
- **号令**：遊軍を呼ぶのは、号令の3回とは別（号令の回数は減らない）。現れたあとの遊軍は、出た側の翼（左から出たら左翼）の部隊として号令を受ける。
- **秘密**：現れるまで、相手には遊軍がいることも兵種も見せない（対戦のサーバーも送らない）。戦場の部隊が1つ少ないことから推し量ることはできる。
- **判定**：
  - 時間切れと膠着の判定（残った兵の割合）では、呼ばなかった遊軍を数に入れない。
  - 星の条件（残った兵が7割以上）では、呼ばなかった遊軍を「無傷で残った」ものとして数える。
  - 膠着の時計は、遊軍が控えていても止まらない（号令が残っていても止まらないのと同じ）。
  - 本陣が討たれたら負け、は変わらない。
- **使える場面**：1人用と対戦の両方。いまの15面の敵は遊軍を使わない。敵が使う仕組み（面のデータに「いつ・どちらから」を書く）だけ用意する。ひな形は遊軍を使わない。保存した陣形には、遊軍に回した部隊も一緒に保存する。
- **画面**：名前は「遊軍」。配置の画面に「遊軍」の枠を1つ、戦闘の画面に「遊軍 左から」「遊軍 右から」のボタンを2つ足す。遊軍を控えさせていない戦いでは、ボタンを出さない。現れたときは、その部隊の上に短く「遊軍」と出す（相手の遊軍も同じ）。枠とボタンの位置は、実際の画面で確かめてから決める。
- **強さ**：測定（balance.md §6）の数字を見たうえで、弱めずにそのまま進める（2026-11-19）。
- **将軍の視点では**、現れるマスが枠の外になるので、「遊軍」の知らせだけを枠の中に寄せて出す（design §5.8.3）。
- **しないこと**：戦闘の画面に、膠着までの残り秒は出さない（2026-11-18）。鶴翼のひな形の弓兵は守備のまま（2026-11-18）。

## 17. チュートリアル（issue #4。2026-11-19 に決定）

- **位置づけ**：1-1 の前に置く、独立した一戦。星はない。初めて「ステージ」を押したときに自動で始まり、ステージ選択の第1章の先頭に「遊び方」として残る（いつでもやり直せる）。
- **教えること**：部隊を置く、部隊を押して方針を変える、開戦、号令、勝ち方（敵の本陣を落とす）。型、陣形の保存、遊軍、視点、倍速、地形は教えない。
- **第1章は変えない**：1-1〜1-4 では方針や号令が使えないままにする。チュートリアルの最後に「先の面で使える」と一言出す。
- **案内**：一歩ずつ進める。画面に一行の指示を出し、押してほしい所だけを目立たせ、ほかの操作はできないようにする。
- **編成**：平地。自軍は本陣と歩兵3つ、敵は本陣と歩兵2つ。敵は守備で動かず、号令も出さない。置くマスは決め打ち。
- **戦闘**：号令の指示を出す間は戦闘を止め、押したら再開する。乱数の種を固定し、毎回同じ展開で必ず勝つ。負けたときの画面は作らない。
- **飛ばす**：「飛ばす」をいつも出す。確かめずに抜け、済んだ扱いにする。
- **記録**：保存に「済み」を1つ足す。最後まで遊ぶか、飛ばすと付く。星が1つでもある保存は、最初から済みとして扱い、自動では始めない。対戦が開く条件は変えない。（対戦が開く条件は、2026-11-20 にやめた。§19）
- **画面**：指示は、配置の画面では面の手がかりの行に、戦闘の画面では号令の下の空きに出す。目立たせるのは、いまの選択中の色の点滅だけ（新しい色や矢印は足さない）。関係のないボタン（型、陣形、遊軍、視点、倍速）は隠す。
- **設計で決めた細部**（design §8）：方針の手順では、真ん中の歩兵を「本陣狙い」にする（敵を全滅させる前に本陣が落ち、「本陣を落とせば勝ち」の文と決着が合うようにするため。最初の案の編成では、本陣が残ったまま全滅で終わった）。最後の一言は、縦長の画面の幅に収めるため「動き方と号令は、先の面で使える」に縮めた。方針を選ぶ所に「『本陣狙い』を選ぼう」の一行を足した。

## 18. モバイル対応（issue #7。2026-11-20 に決定）

iPhone SE（iOS 18）と iPhone 17 Pro（iOS 26）のシミュレータの Safari、Android のエミュレータの Chrome で全画面を測ったうえで決めた（測った数字は design §9.1）。

- **向き**：縦を主にする。スマホの横は、動くが小さいままにする（横長用の配置は作り直さない）。
- **押しやすさ**：見た目は変えず、ボタンの押せる範囲だけを、隣とのすき間の半分まで広げる。効果は控えめ（iPhone SE の縦で、多くのボタンが縦 28px → 34px）。対戦の配置の「−」「＋」は 24×21px → 26×25px にしかならない。これ以上は見た目を変えないとできないので、今回はここまで。
- **ホーム画面への追加**：入れる。家で1人用を遊ぶ人のためのもの（その場で対戦する人は、ブラウザのまま遊ぶ想定）。
  - アイコン（本陣の絵）、名前「陣形合戦」、全画面で開く指定を足す。向きは固定しない。
  - ノッチとホームバーを避ける余白を入れる。ブラウザで開いたときにも効く（横向きの下端の重なりが直る。そのぶん、横向きはさらに少し縮む）。
  - オフラインで遊べるようにする仕組み（Service Worker）は入れない。
  - **iPhone では、ホーム画面の版は Safari と保存が別になる**（通例。未検証）。星は引き継がれず、チュートリアルから始まる。これは受け入れ、移す仕組みも、追加を促す案内も作らない。
- **画面を消さない**：1人用の戦闘のあいだと、対戦の部屋にいるあいだ、画面が消えないようにする（Screen Wake Lock）。Safari は、指を離した直後の頼みしか受け付けないので、押した流れで頼む。画面を閉じて戻ったあとは、次に画面に触るまで効かない。仕組みがない端末では、今までどおり動く。
- **戻ったらすぐつなぎ直す**：対戦中に画面へ戻ってきたとき、通信が切れていたら、待たずにつなぎ直す。
- **確かめ方**：シミュレータまでは作る側で確かめる。実機（触り心地、画面が本当に消えないか、ホーム画面への追加）は、公開したあとに確認表で見る。
- **しないこと**：スマホの横長用の配置、ボタンの見た目の拡大、対戦のロビーの入力欄の変更（縦では、キーボードが出ても欄は隠れず、勝手な拡大も起きなかった）、進み具合を移す仕組み。
- **別に決めること**：対戦が開く条件（第1章を終えるまで閉じている）は、この件と切り離して未決のまま。（2026-11-20 に、条件をやめると決めた。§19）

## 19. 対戦のルール説明（2026-11-20 に決定）

- **対戦の入口**：「第1章の面をすべて勝つまで、対戦は押せない」（§8）をやめる。初めて開いた人でも、タイトルの「対戦」をすぐ押せる。その場で対戦だけ遊ぶ人が入れないため。
- **代わりに、ルールの説明を出す**：初めてロビーを開いたときだけ、自動でダイアログを出す。「閉じる」を押すと「見た」と覚え、次からは自動では出さない。ロビーの右上に「ルール」のボタンを置き、いつでも見られる。
- **文言**（見出し「対戦のルール」と7行）：
  1. 部隊を並べて、2分で陣を作る
  2. 相手の陣は、開戦まで見えない
  3. 開戦したら、部隊は自分で戦う
  4. 号令は3回まで。全軍か翼に出す
  5. 1部隊を遊軍にして、途中で呼べる
  6. 敵の本陣を落とせば勝ち
  7. 時間切れは、兵が多く残ったほう
- **見た目と閉じ方**：陣形の保存の箱と同じ作り（暗い地に金の枠、下の画面は押せない）。「閉じる」のボタン1つで閉じる。箱の外を押しても閉じない。新しい色や飾りは足さない。
- **変えないこと**：チュートリアルは、初めて「ステージ」を押したときに始まるまま（対戦から入った人には自動では出ない）。1人用の面が開く順番、星。
- **書かないこと**：部隊の動き方（前進・守備・迂回・本陣狙い）、ひな形、視点の切り替え、遊軍を呼べる回数と向き。

## 20. 対戦の3つの直し（2026-11-21 に決定）

会場で、同じ Wi-Fi から何組も同時に遊ぶことを見込んで直す（人数は分からないので、多めに備える）。

- **入室と作成の回数の上限**（同じ送信元ごと）：
  - すでにその部屋の席にいる人のつなぎ直しは、入室の回数に数えない（Wi-Fi が一瞬切れて全員が一斉につなぎ直しても、締め出されないように）。
  - 新しく入る人：1分に 120 回まで（いままで 30 回）。部屋を作る：1分に 60 回まで（いままで 10 回）。
  - 上限の目的（4桁のコードの総当たりと、部屋の作りすぎを抑える）は残す。
- **相手が自分で部屋を出たとき**：「部屋を出る」を押したら、ただ切れたのとは別に「出た」と server に知らせる。
  - 配置の途中・結果の画面で出たとき：残った人を、60 秒待たずに、すぐ待機の画面に戻す。そこに「相手が部屋を出ました」と出す。通算成績は、いままでどおり消える。
  - 戦闘の途中で出たとき：戦闘は止めずに最後まで続ける（出た側の部隊は、決めた動き方のまま戦う）。「相手 切断」の代わりに「相手 退出」と出す。決着して結果を見せたあと、残った人が「もう一戦」を押すか、少し（15 秒）たつと、待機の画面に戻す。
  - 通信が切れただけのとき（電波、画面を閉じた）は、いままでどおり「相手 切断」で、戻るのを待つ。
- **対戦の結果の「残った兵」**：自軍も敵軍も、勝ち負けを決めるときと同じ数え方（呼ばなかった遊軍を数に入れない）にそろえる。2人の画面で同じ数字になり、時間切れの勝ち負けと必ず合う。1人用の結果の画面は変えない（星の条件と同じ数え方のまま）。

## 21. スマホの入力欄の崩れ（issue #15。2026-11-22 に決定）

- **起きていたこと**（iPhone のシミュレータ2機種で再現）：名前やコードの欄を押してキーボードが出ると、欄だけが絵から外れて上に飛ぶ。ずれたコードの欄が「部屋を作る」に重なり、欄を押すと下のボタンも押されて、部屋が勝手にできる。
- **直し方**：入力欄を、ゲームの絵と同じ入れ物の中に置き、絵と一緒に動くようにする。欄へのタッチが、下のボタンに届かないようにする。見た目とレイアウトは変えない。
- **入力中の見え方**：iPhone がキーボードに合わせて画面を上へずらすのは、そのままにする。その間、上の「戻る」「ルール」は時計の裏に隠れる。キーボードを閉じると戻る。
- **Android**：入力中は、縦持ち・横持ちの判定をし直さない守りを入れる（キーボードで画面の高さが縮む機種で、画面が組み直されないように）。シミュレータで確かめられないので、未検証と明記し、実機で確かめる。
- **確かめる範囲**：iPhone のシミュレータ2機種（SE と 17 Pro）の Safari、縦持ち、画面のキーボードを出した状態で、対戦の一連の流れ（名前 → 部屋を作る／コードで入る → 配置 → 戦闘 → 結果 → もう一戦）。

## 22. マスを減らす（issue #17 の前半。2026-11-22 に決定）

スマホでは 12×16 のマス（1マス約 28px）が小さく、部隊を押す・1マス動かすのが難しい。絵を大きく見せるためにも、マスを減らす。

- **盤**：戦場は 10×12 マス（いままで 12×16）。部隊を置けるのは各軍とも中央の 8 列 × 4 行で、両端の 1 列ずつは誰も置けない「通り道」。あいだは 4 行。1マスは内部で 36px。
- **盤の決め直し**（同じ日に、実験のあとで決定）：はじめは、触れる試作で 9×12・8×11・6×8 を比べて 8×11（通り道なし、あいだ 3 行）を選んだ。自動の対戦で確かめると、横 8 列だけの盤では、盾兵を 8 部隊並べて前を端から端までふさぐ編成がほかの全部の編成に全勝し、騎兵が敵の後ろまで回れる割合も 66% から 50% に落ちた。行数・弓の距離・コスト・部隊数の上限を変えても直らなかった。配置の 8 列はそのままに、戦場だけ両端に 1 列ずつ足すと、盾兵だけの全勝が消え、回り込める割合は 77% になり、距離の数字（弓の射程など）もいまのまま使える。押しやすさ（配置のマスの大きさ）は 8×11 と同じに保てるので、こちらに決め直した。記録は `exp/grid-tuning` の `docs/experiment-grid-8x11.md`。
- **通り道にしたことの費用**：配置の画面は幅が足りないので、通り道を左右 16px ずつだけ見せる（切れた状態）。戦闘で盤を 30° 回したときの縮みが 0.68 倍から 0.58 倍になり、兵が約 15% 小さく見える。左翼・中央・右翼は、配置できる 8 列のうち 2 列・4 列・2 列（8×11 では 3・2・3 の予定だった）。
- **部隊数と予算**：1軍 12 部隊まで（本陣を含む。いままで 16）。対戦の予算は 24（いままで 36）。兵種ごとのコスト（歩兵2・盾兵3・弓兵3・騎兵4・本陣0）は変えない。
- **部隊数の上限を 11 に下げる条件**（2026-11-22 に承認）：歩兵だけ 11 部隊の編成がほかの全部の編成に勝ち越すなら、上限を 11（本陣を含む）に下げる。通り道つきの盤で測ると、鶴翼の中央が前進のひな形では勝ち越しが起き、守備のひな形では起きなかった（上限 12 でいちばん強い編成は 86〜87%、上限 11 では 92〜94%）。そのため、ひな形を仕上げたあとの計測で決める。勝ち越す編成が出なければ 12 のまま。一人用の面は、どちらになっても通るよう、手持ちも敵も 11 部隊までで作る。
- **対戦の編成**：予算と部隊数の中で、兵種は完全に自由（兵種ごとの上限は置かない）。標準の編成（本陣・歩兵4・盾兵2・弓兵2・騎兵1。予算 24 ちょうど）は、時間切れまでに何も置かなかった人に配る軍と、本陣しか置いていないときのひな形にだけ使う。
- **偏った編成の確かめ**：全部歩兵・全部盾兵・全部弓兵・全部騎兵などの編成を、自動の対戦で標準の編成や各陣形と戦わせる。どれかが勝ちすぎるなら、兵種の上限は足さず、コストの調整で直す。直す前に、結果を見せて相談する。
- **手応えを保つ**：陣形の相性（横陣に鶴翼が勝つ、など）、騎兵の回り込み、1戦の長さが、いまと大きく変わらないことを自動の対戦で確かめる。悪ければ、数字を直す前に相談する。
- **陣形の相性の変わり方**（2026-11-22 に決定）：通り道つきの盤では、ひな形どうしの強さの並びが変わる。鶴翼は中央の方針ひとつで全体の得点率が 0.17（守備）と 0.72（前進。方円が全敗）に振れ、横陣と雁行はどちらでも 0.81・0.83 から 0.86〜0.92 に上がる。ひな形の作り直しを1回入れて、鶴翼を 0.3〜0.6、全敗の形なし、横陣と雁行がいまより強くならないことを狙う。分かっている形の欠点（鋒矢の 6・8 部隊が縦列、方円の 6 部隊で本陣の後ろが空く、鶴翼の 12 部隊が左に寄る）も同じ回で直す。届かなければ、鶴翼の中央を守備のまま進めて、結果を報告する。
- **面と地図**：一人用の 15 面、チュートリアル、対戦の地図は、名前・並び順・その面で学ぶこと・星の条件・敵の陣形の種類を保ったまま、地形と敵の位置と手持ちの数を新しいマスに置き直す。難しさはいまと同じくらいに調整し、全部の面を自動の対戦で確かめる。狭い戦場の面は、通り道を置かず、ふつうの面の半分ほどの幅（5〜6 列）で作る（回り込めない狭さが、その面で学ぶことなので）。一人用の面の手持ちは、面ごとに決まったまま（自由な編成にしない）。
- **保存**：面ごとの最後の配置、保存した陣形、対戦の最後の配置と遊軍は消す（座標が合わなくなるため。自動の詰め直しはしない）。クリアと星の記録、名前、音の設定、対戦のルールを見た印は残す。
- **1マスの実際の大きさ**：ブラウザの上下のバーがなければ、幅 390 のスマホで約 44px。Safari では画面の高さが足りずに全体が縮む。8×11 のときの見込みは iPhone 17 Pro で約 41px（いまは約 28px）、iPhone SE で約 32px（いまは約 21px）で、いまの約 1.5 倍。10×12 は行が 1 つ多いので、操作の欄の高さがいまのままだと約 38px になる。#16 の画面設計で操作の欄を 190 から 150 ほどに詰めて、8×11 と同じ約 41px にする。
- **面の敵の部隊数**：敵も 11 部隊まで（上の条件のため）。いま 13〜16 部隊いる面は、手持ちと同じ比率で減らし、兵力の差（「敵が約2倍」の面など）は保つ。
- **この PR だけを出したときの見た目**（2026-11-22 に決定）：
  - 地面の絵は、36px のマス用に描き直す（立体にしたあとも、地面の模様として使う）。
  - 兵はいまの絵のまま、並びの間隔だけ広げる（兵が立体になるのは §24）。木・柵・城壁の立った絵は、仮に引き伸ばして出す（§24 で置き換える）。
  - 将軍の視点と遠景の絵は、この PR で先になくす（新しい盤に合わせて作り直しても、§24 ですぐ消すため）。真上・斜め・横の視点は、§24 まで残す。
  - 公開の前に画面を見てもらい、見た目が気になるなら公開を待つ（#16 や §24 と一緒に出す）。
- **公開のときの古い画面**（2026-11-22 に決定）：公開の前から開いたままの古い画面が対戦の部屋に入ろうとしたら、サーバーが断る。古い画面には、いまある文の「つながりが切れました」が出る。読み込み直すと新しい版になり、ふつうに入れる。一人用は、古い画面のまま最後まで遊べる。あわせて、新しい版には、次に同じことが起きたときに「新しい版があります。ページを読み込み直してください」と出す仕組みを入れておく（今回の公開では、誰の画面にも出ない）。

## 23. 配置の操作（issue #16。2026-11-22 に決定）

- **対象**：一人用と対戦の両方。操作は共通にし、違いは制限の見せ方だけにする。チュートリアルの文と手順も合わせて直す。
- **置き方**：画面の下に、兵種ごとのカード（手札）を並べる。カードを指で押さえて盤まで引っぱり、離したマスに置く。カードを押して選んでからマスを押す置き方も残す。
- **「＋」「−」をなくす**：対戦の「先に数を増やす」段階をやめる。編成の数という考え方をなくし、盤に置いた部隊（と遊軍）がそのまま自分の軍になる。対戦では、置いた時点でコストが予算から引かれる。
- **外し方**：盤の部隊を手札の欄まで引っぱって離すと外れる（コスト・手持ちが戻る）。引っぱっている間、手札の欄に「ここで外す」と分かる印を出す。部隊を押すと出る「外す」と方針の切り替えは、そのまま残す。
- **見せる数字**：
  - 対戦：上の行に「予算 16/24」の形で使った予算と全体、「部隊 7/11」の形で置いた部隊数（本陣以外）と上限。カードの下に、その兵種のコスト。予算が足りない・部隊数が上限の兵種のカードは暗くして、引っぱれないようにする。
  - 一人用：カードの下に、その兵種の残りの数（「残3」）。0 のカードは暗くする。予算の行は出さない。
  - 予算を目盛りで見せる案は、いまは入れない（行が増えるため。足りなければ足す）。
  - 文言と細かい配置は、実装の前に画面の絵で確かめる。
- **本陣**：最初から、自分のエリアのいちばん後ろの中央に置いてある。引っぱって動かせるが、外せない。手札に本陣のカードは出さない（手札は歩兵・盾兵・弓兵・騎兵の4枚）。
- **最初の盤**：前に使った配置があればそれを出す。なければ、本陣だけが置いてある盤から始める。
- **遊軍**：枠は残す。手札のカードを枠へ引っぱると、その兵種が遊軍になる。盤の部隊を枠へ引っぱると、盤から外れて遊軍になる（方針は引き継ぐ）。枠から盤へ引っぱると盤に置かれ、枠から手札へ引っぱると外れる。カードを選んでから枠を押す入れ方も残す。
- **陣形のひな形**：ボタンは残す。押すと、いま置いている部隊をその形に並べ替える（兵種と数は変えない）。本陣しか置いていないときは、対戦では標準の編成で、一人用では手持ちの全部隊で並べる。遊軍の枠は、ひな形を押しても空に戻さない。
- **保存した陣形**：変えない。対戦で予算を超える陣形を呼び出したら、後ろの部隊から外して収める。
- **引っぱっている間**：
  - 部隊の絵を、指の少し上にずらして出す（指で隠れないように）。
  - 離したら置かれるマスを枠で示す。置けるマスは金、置けないマスは赤（どちらもいまある色）。
  - 手札から、空いている自分のエリアのマスへ：置く。手札から、部隊がいるマスへ：置かない（置き換えない）。
  - 盤の部隊を、別の部隊がいるマスへ：入れ替える。
  - エリアの外や盤の外で離したとき：手札からなら何も起きない。盤の部隊なら元のマスへ戻る。
  - 指を置いてから少し（内部の 8px ほど）動いたら引っぱり、動かさずに離したら「押した」とみなす。
  - 対戦で「完了」を押したあとは、引っぱれない。

## 24. 兵と地形を立体にする（issue #17 の後半。2026-11-22 に決定）

- **ねらい**：どの部隊が歩兵・盾兵・弓兵・騎兵かが、説明なしで分かること。いまは兵が小さく（1人 5×5〜5×8 ドット）、真上からの絵で、人や馬に見えない。
- **技術**：スプライトスタッキング（上から見た薄い層を、同じ角度で回し、縦をつぶし、1層ごとに 1px ずつ上へずらして重ねる）。issue に貼られたスキルは手順の参考にするだけで、インストールしない。
- **絵の作り方**：いままでどおり、文字で書いたデータ（4方向の絵）から、ゲームの中で立体に削り出す。画像ファイルは置かない。色はいまの色の一覧だけ。うまくいかなければ、Codex の画像生成で4方向の絵を作る方法を試す。
- **1部隊の見せ方**：小さめの兵3体。兵が減ったら 3体 → 2体 → 1体と減らす。
- **絵の仕上げ**：試作の絵は簡素なので、本番では描き込む。新しいマス（1マス 36px）に合わせて少し大きく描き直す、全兵種に歩く動きを付ける、輪郭を付けて重なっても1体ずつ見分けられるようにする。本体に入れる前に、2回目の試作ページで見てもらう。
- **見る角度**：配置の画面は盤を回さない（傾きだけ付ける。マスを大きく保つため）。開戦のときに盤が 30° までゆっくり回り、戦闘は盤全体を縮めて見せる（戦闘中は部隊を押す操作がないため）。
- **視点**：「視点」のボタンは、盤の向きの切り替え（右斜め 30°・左斜め・横 90°・後ろ 0°）に置き換える。真上と将軍の視点はなくす。将軍で使っていた遠景の絵は使わなくなる。
- **地形**：森の木・柵・城壁・城門は、兵と同じ方法で立体にする。丘は、なだらかな斜面として地面を持ち上げる（丘のかたまりの中央ほど高い）。丘の上の兵は、その高さのぶん持ち上げて描く。配置の画面では、持ち上がった面を押すとそのマスが選ばれる。丘の効果は変えない。平地・川・霧・瓦礫は地面の模様のままで、盤と一緒に回す。丘の高さは、2回目の試作で低（5px）・中（9px）・高（13px）を比べて、中（いちばん高い所で 9px）に決めた。
- **戦闘での兵の大きさ**（2026-11-22 に決定。2回目の試作で 4 つを比べた）：盤は 10×12 で 0.58 倍に縮むが、兵はその中間（配置のときの約 0.79 倍）で描く。兵を縮めない案は隣の部隊と重なりやすく、盤と同じだけ縮める案はドットがにじみ、小さく作り直す案は描き込みが減る。
- **兵の残りの見せ方**（2026-11-22 に決定）：兵が減った部隊にだけ、足もとに細い棒（高さ 2px、その軍の色）を出す。無傷の部隊には出さない。3体では 3 段階しか見せられず、100% と 70% の部隊が同じ見た目になるため。部隊を押したときの「兵・士気」の数字は残す。棒は新しい要素なので、本体に入れる前に試作に足して見てもらう。
- **重さ**：試作（層ごとの描き方、32 部隊 × 3体）は、ユーザーのスマホで 1秒あたり 56〜59 回描けた。
- **進め方**：時間をかけてよいので、納得のいく見た目を作る。
