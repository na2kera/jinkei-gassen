# 陣形合戦 — 決定事項

2026-11-16 の聞き取り（Q1〜Q24）で合意した内容。ゲームの中身はこの文書が正で、「どう作るか」は `design.md` に書く。
ここにない細部で、作る側が仮に決めたものは `assumptions.md` に書く。

## 1. どんなゲームか

- 古代中国風の戦場で、部隊を並べて陣形を組み、敵とぶつける戦術シミュレーション。
- 漫画「キングダム」の陣形から着想したが、作品の名前・人物・固有の設定・絵柄は使わない。世界観と将は自作する。
- 鶴翼・魚鱗・鋒矢・方円などの陣形名は、兵法の一般の用語なので使う。
- 名前は「陣形合戦」。リポジトリは `~/dev/vite/jinkei-gassen`。

## 2. 遊びの骨組み

| 項目 | 決定 |
|---|---|
| 配置 | マス目に吸い付く。1マスに1部隊。部隊の中に小さな兵が並んで見える |
| 戦闘 | 配置が終わると自動で進む。動きはなめらか |
| 介入 | 戦闘中に号令を出せる（§7） |
| 遊ぶ場所 | PC のブラウザを基準に作り、スマホでも遊べるようにする |
| モード | 1人用のステージクリア型と、友達との1対1オンライン対戦 |

## 3. 見た目

- ドット絵。小さな兵が部隊ごとに並んで動き、ぶつかる。部隊は色と旗で見分ける。
- 視点は、配置中は真上からの見下ろしに固定する。
- 戦闘中は「真上」と「斜め見下ろし」を切り替えられるようにする。ただし先に真上だけで完成させ、斜めはあとから足す。そのために、戦闘の計算と描画を分けて作る。
- 画面の作りは、超富豪で合意した好みに合わせる：ドット調（平らな塗り、2ドット単位の枠、ドット文字）、表示する情報は最小限、グラデーション・ぼかした影・光彩・角丸は使わない。

## 4. 兵種と将

| 兵種 | 役割 |
|---|---|
| 歩兵 | 攻守のバランス型。数の主力 |
| 盾兵 | 足が遅いが、正面からの攻撃に強い。受け止め役 |
| 騎兵 | 足が速い。側面や背後を突くと強いが、正面の盾兵には弱い |
| 弓兵 | 離れて攻撃できるが、接近されると脆い |

- 各軍に総大将の本陣を1部隊置く。**本陣が討たれたら、その時点で負け**。
- 本陣は周囲の味方の士気を上げる。前に出すほど危険になる。
- 個性のある将を部隊に配属する仕組みは、あとから足せる作りにしておく。

## 5. 戦場と配置

- 自軍が部隊を置ける範囲は、**横12 × 奥行き6 を標準**とする（一旦の決定。遊んで合わなければ見直す）。
- 戦場全体は、自軍の配置エリア・中間地帯・敵軍の配置エリアが縦に並ぶ。
- ステージごとに広さを変えられる作りにする。対戦は標準の広さに固定する。
- 置ける部隊の決め方：
  - ステージは手持ちが決まっていて、並べ方だけを考える。
  - 対戦は、兵種ごとの値段と予算があり、その中で自由に編成する。
  - どちらも、本陣を含めて15部隊前後を目安にする。
- 地形は4種。マスごとの性質として作る。対戦用の戦場は左右対称の地形だけを使う。

| 地形 | 効果 |
|---|---|
| 丘 | 上にいる側が有利。弓が遠くまで届く |
| 森 | 騎兵の足が止まり、弓が当たりにくい |
| 川 | 渡っている間は足が遅く、攻撃に弱い |
| 柵・城壁 | 守る側が正面から崩されにくい。攻城・防衛のステージ用 |

## 6. 陣形と戦闘ルール

### 陣形

- **陣形の名前による効果は付けない**。強さは位置関係の共通の決まりだけで決まる：側面や背後から攻められると弱い、隣に味方がいると崩れにくい、囲まれると士気が落ちる、など。
- 並べ方が有名な型に近いと、陣形名（「鶴翼の陣」など）を表示する。表示だけで、効果はない。
- 配置のとき、ひな形（鶴翼・魚鱗・鋒矢・方円など）を選ぶと、手持ちの部隊がその形に自動で並ぶ。そこから手で直せる。ゼロから置くこともできる。
- 自分の配置に名前を付けて保存し、呼び出せる。

### 部隊の方針

配置のときに、部隊ごとに次の4つから1つを選ぶ。相手からは見えない。

| 方針 | 動き |
|---|---|
| 前進 | 正面の敵へまっすぐ進む |
| 守備 | その場を動かず、来た敵を受け止める |
| 迂回 | 外側から回り込み、敵の側面や背後を狙う |
| 本陣狙い | 途中の敵をなるべく避けて、敵の本陣へ向かう |

- 兵種ごとに初期設定を付ける（盾兵は守備、騎兵は迂回など）。ひな形を選ぶと方針も一緒に入る。

### 士気と敗走

- 部隊は兵数と士気を持つ。士気が尽きると、兵が残っていても敗走して戦場から消える。
- 士気が下がる：側面や背後から攻められた、囲まれた、隣の味方が敗走した、兵が大きく減った。
- 士気が保たれる・上がる：隣に味方がいる、本陣が近い、敵を敗走させた。
- 隣がつられて崩れる「総崩れ」が起きることを狙う。

### 勝敗と1戦の長さ

- 本陣を討つと勝ち。
- 本陣以外の部隊がすべて敗走・全滅した側は、その時点で負け。
- 1戦は最長3分。2倍速の早送りを付ける。
- 時間切れ：対戦は、残った兵力の割合が多いほうの勝ち。同じなら引き分け。ステージは面ごとに決める（ふつうの面は負け、防衛の面は守り切れば勝ち）。
- 膠着：だれも攻撃せず、だれも動こうとしないまま10秒たったら、3分を待たずにそこで終える（味方に引っかかって進めないだけの部隊は、動こうとしているので数えない。号令が効いているあいだと、面の敵の予定された号令が残っているあいだも数えない。細かい決まりは `design.md` §3.6.4）。勝ち負けは時間切れと同じ決め方（2026-11-17 にユーザーが決めた。守備どうしが向き合って、時間切れまで待つだけの戦いをなくすため）。
- ステージ独自の勝利条件（「敵の砦の門を破れ」など）も作れるようにする。

## 7. 号令

- 相手は、全軍・左翼・中央・右翼から選ぶ。配置した横位置で、部隊が自動的に左翼・中央・右翼に分かれる。
- 操作は「相手を選ぶ → 号令を選ぶ」の2回押すだけ。
- 種類は3つ。

| 号令 | 効果 |
|---|---|
| 突撃 | 方針を捨てて正面の敵へ突っ込む。しばらく攻撃力が上がり、守りが下がる |
| 堅守 | その場で止まって守りを固める。しばらく守りが上がり、士気が少し戻る |
| 後退 | 自陣側へ下がる。下がっている間は背中を見せるので、追われると危険 |

- 1戦に合計3回まで。
- 突撃と堅守の効果は10秒ほど続き、切れたら元の方針に戻る。
- 出した号令は相手にも見える（「敵右翼、突撃」の表示と、太鼓や旗の演出）。
- 効果の長さや強さの数字は、遊びながら調整する。

## 8. ステージ（1人用）

- 敵の配置（どこに何の兵種がいるか）は配置中に見せる。敵の方針は見せない。
- 面によって「霧で敵の一部が見えない」などの変化を付けられる作りにする。
- 全部で15面ほど、3章。
  - 第1章 平原（5面）：遊び方を覚える。歩兵だけ → 盾兵 → 弓兵 → 騎兵と方針 → 号令を使う決戦。説明文を読ませず、面を解くと覚える作りにする。
  - 第2章 地形（5面）：丘の取り合い、森の待ち伏せ、川を渡る戦い、谷の狭い道、兵力で劣る戦い。
  - 第3章 攻城と防衛（5面）：柵を守り切る、砦を攻める、挟み撃ちにされる、少数で時間を稼ぐ、最後の大決戦。
- 前の面を勝つと次の面が開く。
- 対戦は、第1章を終えると開く。
- 面は「地形・敵の配置と方針・手持ちの部隊・勝利条件」を書いたデータとして作る。
- 評価は星3つ：勝てば1つ、自軍の兵が半分以上残れば2つ、7割以上で3つ。
  - 最初は「8割以上で3つ」としたが、第1章の 1-2・1-3・1-4 では、約1000通りの配置を試しても8割に届かなかった（最良で 78%・77%・72%）。2026-11-17 に7割へ下げた。
- 戦闘後に、簡単な振り返り（部隊ごとの戦果、どこが崩れたか）を表示する。

## 9. 対戦（友達と1対1）

1. 1人が部屋を作ると4桁のコードが出る。もう1人がコードを入れて入室する。
2. 対戦用の戦場（平原、中央に丘、中央に川、両脇に森など。どれも左右対称）から、毎回ランダムに1つ選ばれる。
3. 編成と配置は120秒。お互い相手が見えない。ひな形や保存した陣形を使える。2人とも「完了」を押せば、時間を待たずに進む。時間切れなら、その時点の配置で始まる。
4. 両軍の配置が同時に公開され、数秒の間を置いて戦闘が始まる（最長3分）。
5. 勝敗と振り返りを表示する。両者が「もう一戦」を押すと、同じ部屋のまま2に戻る。

- 1戦ごとに決着し、部屋にいる間の通算成績（例：2勝1敗）を表示する。何戦やるかは自由。
- 通信が切れても戦闘は止めない。切れた側の部隊は方針どおりに戦い続け、号令だけが出せない。同じ部屋に戻れば、その時点の戦況から続きを見て、号令も出せる。
- 配置中に切れた場合は、制限時間が来た時点の配置で始まる。
- 片方が60秒いない状態で1戦が終わったら、部屋は待機に戻り、残った人に「相手を待っています」と表示する。
- 戦闘の計算は、サーバー側で1つだけ行う。

## 10. 保存

- アカウントは作らない。
- ステージのクリア状況、星の数、保存した陣形、対戦で使う名前は、その端末のブラウザに保存する。
- 対戦の途中で切れても、端末に保存した識別用の番号で同じ部屋に戻れる。
- サーバーへの保存（記録の引き継ぎ、通算成績）は、あとから足せる。

## 11. 技術

| 部分 | 使うもの |
|---|---|
| 画面と描画 | Phaser + TypeScript + Vite |
| 戦闘の計算 | 素の TypeScript + Vitest。画面から切り離し、1人用はブラウザで、対戦はサーバーで同じものを動かす |
| 対戦サーバー | Cloudflare Workers + Durable Objects（1部屋 = 1 Durable Object、WebSocket） |
| 公開 | Cloudflare Workers |
| 構成 | pnpm のモノレポ（engine / server / client） |

- React は使わない。メニューや部屋のコード入力は、Phaser と素の HTML で作る。
- バージョンは `design.md` に固定して書く。変えるときは相談する。

## 12. 作る順番

段階ごとに動かして確かめてから、次へ進む。

1. **戦闘の土台**：平原1面。4兵種と本陣、マス目への配置、方針、自動戦闘、士気と敗走、号令3種、勝敗の判定。絵は仮のもの。
2. **1人用の最初の形**：第1章の5面、ひな形、陣形名の表示、星の評価と振り返り、ドット絵の兵と戦場、音。
3. **対戦**：サーバー、部屋とコード、予算での編成、120秒の配置、同時公開、号令のやり取り、切断と復帰。戦場は平原だけ。
4. **地形と残りのステージ**：丘・森・川・柵と城壁、第2章と第3章の10面、対戦用の地形つき戦場。
5. **仕上げの追加**：自分の陣形の保存、斜め見下ろし視点。

## 13. あとから足す候補

決めていないが、足せる余地を残しておくもの。

- 地形：沼、崖、橋、火計の草原
- 兵種：戦車、弩兵、軽騎兵
- 個性のある将を部隊に配属する
- 疲労（走り続けたり戦い続けたりすると弱くなる）
- 面ごとの課題（「号令を使わずに勝つ」など）
- 協力プレイ（2人で1つの軍）
- キャンペーン型（部隊が育つ、損害を持ち越す）
- 自由モード（地形・敵陣形・兵数を選んで試す）
- 先に2勝で決着する形式
- サーバーへの保存とアカウント
