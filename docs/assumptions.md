# 陣形合戦 — 仮に決めたこと

聞き取りで決めていない細部を、作る側が仮に決めたもの。違っていたら、ここを直して作り直す。

| # | 項目 | 仮の決定 | 理由 |
|---|---|---|---|
| S1 | 対戦の予算 | 予算 36。歩兵 2、盾兵 3、弓兵 3、騎兵 4。本陣は無料で必ず1つ。本陣以外は 1〜15 部隊 | 平均の値段が 2.6 ほどで、14部隊前後になる |
| S2 | 中間地帯の奥行き | 4マス | 開戦から数秒で接触し、迂回する余地も残る |
| S3 | ステージの敵の号令 | 面のデータに「何秒で、どの翼に、何を」と書いておく。状況を見て判断はしない | 面の難しさを作る側が決められる。再現もできる |
| S4 | 本陣の方針 | 守備と前進だけ | 本陣が迂回や本陣狙いをすると、負け方が分かりにくい |
| S5 | 本陣への号令 | 堅守と後退はかかる。突撃はかからない | 「全軍突撃」で本陣まで突っ込むのを防ぐ |
| S6 | 敗走した部隊 | 立て直さない。5秒で消える | 決着が早くなり、総崩れがはっきり見える |
| S7 | 時間切れの引き分け | 残った兵の割合の差が 0.01 未満 | 完全に同じ値はまず起きないため |
| S8 | 配置の制限時間に間に合わなかったとき | 最後に検査を通った下書きを使う。なければ、既定の編成を横陣で並べる | 「その時点の配置で始まる」を、不正な配置でも成り立たせる |
| S9 | 部屋のコード | 4桁の数字。誰もいない状態が10分続いたら消す | 口頭やメッセージで伝えやすい |
| S10 | 場面を送る回数 | 毎秒5回。client があいだを補う | 通信量を抑えつつ、動きはなめらかに見える |
| S11 | 陣営の色 | 自軍は藍、敵軍は朱 | 小さなドットでも見分けやすい。色だけに頼らず、旗の形でも分ける |
| S12 | 兵の表示 | 1部隊に最大16人の兵を描く | 1マス 24px に収まり、減り方が目で分かる |
| S13 | 画面の向き | 縦長と横長の両方に対応し、起動時と向きが変わったときに切り替える | PC 基準でスマホにも対応、の決定を満たす |
