# 陣形合戦 — 設計書

> ゲームの中身は `decisions.md` が正で、この文書は「どう作るか」を決める。
> 作る側が仮に決めた細部は `assumptions.md` にまとめる。
> 数字（速さ・攻撃力・士気の増減など）はすべて初期値で、§3.9 の合格条件を満たすように調整してよい。合格条件のほうが数字より優先する。

## 2. いちばん大事な分け方

**engine が計算するのは「部隊」であって「兵」ではない。**

- engine が持つのは、1軍あたり最大16部隊ぶんの、位置・向き・兵数・士気・状態だけ。
- 部隊の中に並ぶ小さな兵は、client が兵数から描き起こす飾りで、engine は関知しない。
- 戦闘を映す側（client）は、engine の状態を直接読まず、`BattleSource`（§5.2）から届く「場面」だけを描く。1人用と対戦で同じ描画が使え、あとから斜め視点も足せる。

## 3. engine

### 3.1 原則

- **再現できる**。同じ初期状態・同じ種・同じ入力からは、同じ結果が出る。`Math.random`・`Date.now`・時計・通信に触れない。乱数は状態の中に持つ（32ビットの種から進める）。
- **時間は刻みで進む**。1刻み = 0.1秒（`DT = 0.1`）。engine は実時間を知らない。呼ぶ側が `step` を呼んだ回数だけ進む。
- **状態は JSON にそのまま保存できる形**。`Map`・`Set`・クラスのインスタンス・`undefined` の値を持たない。
- **例外を投げない**。不正な入力はエラーの結果として返す。
- `step` は渡された状態を書き換える（毎刻みの複製を避けるため）。複製が要る側は自分で複製する。
- 部隊の処理は id の順。ダメージと士気の変化は、全部隊ぶんを計算してから同時に適用する（処理順による有利不利をなくす）。

### 3.2 座標と戦場

- 単位はマス。戦場は横 `width` × 縦 `height`。標準は 12 × 16（自軍の配置エリア6 + 中間地帯4 + 敵軍の配置エリア6）。
- 陣営は `0` と `1`。陣営0の配置エリアは下側（y が 10〜16）、陣営1は上側（y が 0〜6）。陣営0の「前」は y が減る向き、陣営1は増える向き。
- 部隊の位置はマスの中心（列 + 0.5、行 + 0.5）から始まり、戦闘中は連続した値で動く。
- 地形はマスごとに持つ（§3.8）。段階1〜3はすべて平地だが、型と受け渡しは最初から入れておく。
- 翼は、配置した列で決まる：自分から見て左の3分の1が左翼、右の3分の1が右翼、あいだが中央。陣営1は向きが逆なので、列の大きいほうが左翼になる。

### 3.3 型

```ts
type Side = 0 | 1;
type Kind = 'infantry' | 'shield' | 'cavalry' | 'archer' | 'hq';   // 段階4で 'gate' を足す
type Stance = 'advance' | 'hold' | 'flank' | 'hunt';               // 前進・守備・迂回・本陣狙い
type OrderKind = 'charge' | 'brace' | 'retreat';                   // 突撃・堅守・後退
type OrderTarget = 'all' | 'left' | 'center' | 'right';
type Terrain = 'plain' | 'hill' | 'forest' | 'river' | 'fence' | 'wall';

interface Placement { kind: Kind; col: number; row: number; stance: Stance }

interface Field {
  width: number; height: number;
  terrain: Terrain[];                       // 行優先。長さは width × height
  zones: [Zone, Zone];                      // 陣営ごとの配置エリア（マスの矩形）
}

interface BattleSetup {
  field: Field;
  armies: [Placement[], Placement[]];       // 戦場の座標で書く
  seed: number;
  maxTicks: number;                         // 標準は 1800（3分）
  timeout: 'compare' | 'side0_wins' | 'side0_loses';
  scriptedOrders?: { tick: number; side: Side; target: OrderTarget; kind: OrderKind }[];  // ステージの敵の号令
}

interface Unit {
  id: number; side: Side; kind: Kind; wing: 'left' | 'center' | 'right';
  x: number; y: number; fx: number; fy: number;     // 位置と、向きの単位ベクトル
  men: number; maxMen: number; morale: number;      // 士気は 0〜100
  stance: Stance; home: { x: number; y: number };
  status: 'active' | 'routing' | 'gone';
  goneReason: null | 'routed' | 'destroyed';
  target: number | null;
  order: null | { kind: OrderKind; untilTick: number };
  // ほかに、迂回の進み具合・騎兵の助走距離・最後に撃たれた刻み・戦果（与えた損害、受けた損害、敗走させた数）を持つ
}

interface BattleState {
  tick: number; rng: number; field: Field; units: Unit[];
  ordersUsed: [number, number];
  maxTicks: number; timeout: BattleSetup['timeout'];
  outcome: null | { winner: Side | 'draw'; reason: 'hq' | 'wipeout' | 'timeout' | 'gate'; tick: number };
  // ほかに、開戦時の兵数の合計、最初に敗走した部隊の記録、予定された号令
}
```

### 3.4 公開する関数

```ts
createBattle(setup: BattleSetup): Result<BattleState>      // 配置を検査してから作る
step(state: BattleState, orders: OrderInput[]): BattleEvent[]   // 1刻み進める。決着後は何もしない
canOrder(state, side, target, kind): Result<true>          // 回数・決着済み・対象が残っているか
viewFor(state: BattleState, viewer: Side | 'both'): BattleView  // 映す側に渡す場面。相手の方針を落とす
summarize(state: BattleState): BattleSummary               // 振り返り用（残った兵の割合、部隊ごとの戦果、最初に崩れた部隊）

validateArmy(placements, zone, limits): ArmyError[]        // マスの重なり・エリア外・本陣の数・予算・部隊数
armyCost(placements): number
defaultStance(kind): Stance
wingOf(col, field, side): 'left' | 'center' | 'right'

listTemplates(): TemplateInfo[]                            // ひな形（§3.7）
applyTemplate(id, roster, zone, side): Placement[]
recognizeFormation(placements, zone, side): { id: string; name: string } | null

STAGES: Stage[]                                            // ステージのデータ（§3.10）
PVP_RULES: { budget, costs, maxUnits }                     // 対戦の予算
```

- `BattleEvent` は、映す側が演出に使う出来事：号令が出た、部隊が敗走した、部隊が全滅した、騎兵の突入が決まった、決着した。
- `BattleView` の部隊は、位置・向き・兵数・士気・状態・かかっている号令まで。**相手の部隊の方針は含めない**。対戦では、サーバーが席ごとに `viewFor` を通してから送る。

### 3.5 部隊の数字（初期値）

| 兵種 | 兵数 | 速さ（マス/秒） | 近接の攻撃 | 特徴 |
|---|---|---|---|---|
| 歩兵 | 100 | 1.0 | 3.0 | なし |
| 盾兵 | 100 | 0.7 | 2.2 | 正面から受けるダメージは 0.45 倍。正面からの騎兵の突入を無効にする |
| 騎兵 | 60 | 2.2 | 3.6 | 助走をつけて当たると突入（下記） |
| 弓兵 | 80 | 0.9 | 1.2 | 4.5 マス先まで撃てる（毎秒 2.4）。近接で受けるダメージは 1.3 倍 |
| 本陣 | 80 | 0.6 | 2.6 | 受けるダメージは全方向 0.7 倍。3.5 マス以内の味方の士気を支える |

- 部隊の大きさは半径 0.45。近接が届く距離は中心どうしで 1.05。
- 味方どうしは重ならないように押し合うが、通り抜けはできる（詰まって動けなくなるのを防ぐ）。敵は通り抜けられない。

### 3.6 1刻みの中身

順番は次のとおり。

1. **号令を受け付ける**（§3.6.5）。予定された号令（ステージの敵）もここで出す。
2. **切れた号令を外す**。
3. **狙いと行き先を決める**（§3.6.1）。
4. **動く**。地形と号令の倍率をかけた速さで行き先へ。敵にぶつかったら止まるか、横へずれる。戦場の外へは出ない。
5. **向きを変える**。狙いのほうへ、毎秒の回転の上限つきで（歩兵と弓兵 180°、盾兵 120°、騎兵 240°、本陣 120°）。近接で戦っている部隊は、いまの狙いを向いたままになる。そのため、別の敵が横や後ろから当たると、側面・背面の扱いになる。
6. **戦う**（§3.6.2）。全部隊のダメージを計算してから、まとめて引く。
7. **士気を動かす**（§3.6.3）。兵数が0になった部隊は全滅、士気が0になった部隊は敗走にする。
8. **敗走中の部隊を動かす**。自陣の奥へ 1.3 倍の速さで逃げる。その間も攻撃は受ける。戦場の端を越えるか、5秒たつと消える。立て直しはしない。
9. **決着を調べる**（§3.6.4）。

#### 3.6.1 方針ごとの動き

| 方針 | 動き |
|---|---|
| 前進 | 「距離 + 横のずれ」がいちばん小さい敵を狙い、近づいて戦う。狙いは、消えるか、ほかの敵が 1.0 以上近くなるまで変えない。近接の距離に敵がいれば、その敵と戦う |
| 守備 | 置かれた場所を動かない。近接の距離に来た敵と戦う。4マス以内に敵がいればそちらを向く。押されてずれたら元の場所に戻る |
| 迂回 | 自分に近いほうの端の列へ出る → 端に沿って、開戦時の敵軍の重心の行まで進む → そこからいちばん近い敵へ向かう。途中で 1.5 マス以内に敵が来たら、迂回をやめてその敵と戦う |
| 本陣狙い | 敵の本陣へ向かう。2.5 マス以内の敵（本陣以外）からは離れるように曲がる。進む向きの正面に敵がいて近接の距離に入ったときだけ、その敵と戦う。それ以外は進み続ける（すれ違う敵から側面を打たれる危険がある） |

- 弓兵は、撃てる距離に敵が入ったら、そこで止まって撃つ（守備ならその場から撃つ）。1.2 マス以内に敵がいる間は撃てず、近接で戦う。味方には当たらない。
- 本陣が選べる方針は、守備と前進だけ。初期設定は守備。
- 初期設定：歩兵は前進、盾兵は守備、騎兵は迂回、弓兵は前進、本陣は守備。
- 狙いが敗走・全滅したら、方針に従って次を決める（守備は元の場所へ戻る）。

#### 3.6.2 ダメージ

近接で、攻める部隊 A が守る部隊 D に毎秒与える損害（兵数）：

```
攻撃 × √(Aの兵数 ÷ Aの最大兵数) × 相性 × 向き × 号令 × 地形 × ばらつき(0.9〜1.1)
```

- **向き**：D の向きに対して、A が正面（±60°以内）にいれば 1.0、側面なら 1.5、背面（±120°より後ろ）なら 2.0。
- **相性**：騎兵 → 弓兵 1.5、歩兵 → 弓兵 1.2、騎兵 → 盾兵の正面 0.6。ほかは 1.0。
- **盾兵の正面**：向きの 1.0 の代わりに 0.45 をかける（側面・背面は盾の効果なし）。
- **騎兵の突入**：騎兵が、戦わずに 2.0 マス以上走ってから敵に当たると、その瞬間に兵数 12 × 向きの損害と、士気への衝撃（正面 −10、側面 −18、背面 −25）を与える。盾兵の正面に当たった場合は、損害が 0.2 倍で士気への衝撃はなく、騎兵のほうが兵数 8 と士気 8 を失う。森の中では起きない。戦いから離れてまた 2.0 マス走れば、もう一度できる。
- **弓**：狙いは撃てる距離の中でいちばん近い敵。損害は毎秒 2.4 に、盾兵の正面なら 0.4、森の中の相手なら 0.5 をかける。

#### 3.6.3 士気

- 損害を受けたとき：

```
士気の減り = (失った兵数 ÷ 最大兵数) × 120 × 向き × 支え
```

  - 向き：正面 1.0、側面 1.6、背面 2.4。弓で受けた損害は 0.6。
  - 支え：1.6 マス以内の味方1部隊ごとに 0.15 軽くなる（3部隊まで）。本陣が 3.5 マス以内なら、さらに 0.7 倍。堅守の号令中は、さらに 0.6 倍。
- 囲まれている（正面・側面・背面のうち2つ以上の向きから近接で攻められている）間、毎秒 −2。
- 2.0 マス以内の味方が敗走した瞬間、−12。全滅なら −6。
- 自分が狙っていた敵が敗走した瞬間、+8。2.5 マス以内でほかの敵が敗走したら、+3。
- 2.0 マス以内に敵がおらず、2秒のあいだ撃たれていなければ、毎秒 +1.5。本陣が 3.5 マス以内なら、いつでも毎秒 +1。上限は 100。

#### 3.6.4 決着

調べる順番は次のとおり。同じ刻みで両軍が条件を満たしたら引き分け。

1. 本陣が全滅・敗走した側の負け（理由 `hq`）。
2. 本陣以外の部隊がすべて全滅・敗走した側の負け（理由 `wipeout`）。
3. `maxTicks` に達したら時間切れ（理由 `timeout`）。`compare` は、残った兵数 ÷ 開戦時の兵数（本陣を含む。敗走した部隊は0と数える）が大きいほうの勝ちで、差が 0.01 未満なら引き分け。`side0_wins`・`side0_loses` はステージ用。

#### 3.6.5 号令

- 1軍につき合計3回。対象の翼に動ける部隊が残っていなければ、受け付けない（回数も減らない）。
- 同じ部隊に新しい号令がかかったら、前の号令を上書きする。

| 号令 | 続く長さ | 効果 |
|---|---|---|
| 突撃 | 10秒 | 方針が前進になる。攻撃 1.3 倍、受けるダメージ 1.2 倍、速さ 1.25 倍。かかった瞬間に士気 +5。本陣にはかからない |
| 堅守 | 10秒 | その場で止まる。受けるダメージ 0.7 倍、士気の減り 0.6 倍。かかった瞬間に士気 +10 |
| 後退 | 6秒 | 自陣の奥へまっすぐ下がる（向きも後ろを向く）。配置エリアのいちばん奥の2行まで来たら止まる |

- 号令が切れたら、元の方針に戻る。守備の部隊は、切れた時点の場所を新しい持ち場にする。

### 3.7 ひな形と陣形名

ひな形は、手持ちの部隊（兵種ごとの数）と配置エリアを受け取って、配置と方針を返す関数。部隊の数が 6〜16 のどれでも、エリアに収まり、重ならず、全部隊を使い切ること。

| id | 名前 | 形（自軍から見て。上が敵） | 兵種の割り当てと方針 |
|---|---|---|---|
| `line` | 横陣 | 横一列に2段 | 前列に盾兵と歩兵（前進）、後列に弓兵、両端に騎兵（迂回） |
| `crane` | 鶴翼 | V字。両翼が前に張り出し、中央が下がる | 中央に盾兵（守備）と弓兵、両翼に歩兵（前進）、翼の先に騎兵（迂回） |
| `scale` | 魚鱗 | 先がとがった三角形で、中央が厚い | 先に歩兵（前進）、中に盾兵（前進）、後ろに弓兵、騎兵は後ろの両脇（前進） |
| `arrow` | 鋒矢 | 矢印。細く深い縦の列で、先が矢じり | 矢じりに騎兵（本陣狙い）と歩兵（前進）、軸に盾兵（前進）、弓兵は後ろ |
| `ring` | 方円 | 本陣を囲む輪 | 外側に盾兵と歩兵（守備）、内側に弓兵（守備）、騎兵は輪の中（守備） |
| `crescent` | 偃月 | 弓なり。中央が前に出て、両翼が下がる | 中央の前に歩兵と騎兵（前進）、両翼に盾兵（守備）、弓兵は後ろ |
| `echelon` | 雁行 | 斜めの段々 | 前の段から歩兵（前進）、盾兵（前進）、弓兵。騎兵は前に出た側の端（迂回） |

- 本陣は、どのひな形でも後ろの中央（方円は輪の中心）。
- 兵種が足りない・余るときは、役割の近い兵種で埋める（盾兵 ↔ 歩兵、騎兵 → 歩兵、弓兵 → 歩兵の後ろ）。
- **陣形名の判定**：本陣を除いた配置のマスの集合 P と、同じ手持ちで作った各ひな形のマスの集合 T を比べる。横に ±2、縦に ±1 ずらした中で、`|P∩T| ÷ max(|P|, |T|)` がいちばん大きい値を、そのひな形の点とする。点が 0.75 以上で、2番目との差が 0.05 以上あるひな形の名前を返す。兵種と方針は見ない。雁行は左右どちら向きも同じ名前にする。

### 3.8 地形（段階4で効かせる）

| 地形 | 効果（初期値） |
|---|---|
| 丘 | 丘の上から低い相手への攻撃 1.2 倍。低い相手から受けるダメージ 0.85 倍。弓の届く距離 +1.5。登るときの速さ 0.8 倍 |
| 森 | 速さ 0.8 倍（騎兵は 0.5 倍）。騎兵の突入なし。森の中の部隊が弓から受ける損害 0.5 倍 |
| 川 | 速さ 0.5 倍。川の中の部隊は攻撃 0.7 倍、受けるダメージ 1.3 倍 |
| 柵 | 柵のマスにいる部隊は、柵の外からの近接ダメージ 0.55 倍、弓の損害 0.5 倍。柵の部隊への騎兵の突入なし。柵を通る速さ 0.4 倍 |
| 城壁 | 通れない。弓も越えない |

- 部隊の地形は、中心があるマスで決める。
- 城壁で直進できないときのために、段階4で、マス目の上の経路探し（幅優先）を入れる。
- 門（`gate`）は動かず、攻撃せず、士気を持たない部隊として足す。「門を破れ」の面では、門の全滅が勝ちの条件になる。
- 段階4に入る前に、この節の細部を `design.md` に書き足し、レビューを受ける。

### 3.9 合格条件（段階1の関門）

人が触って確かめる代わりに、画面なしの自動テストで「陣形ゲームとして成り立っている」ことを確かめる。**これが通るまで段階2に進まない**。乱数の種を変えた複数回（20回以上）で調べる。

| # | 条件 |
|---|---|
| A1 | 同じ軍を鏡写しに置いた戦いは、陣営0の勝率が 35〜65% に収まる（陣営による有利不利がない） |
| A2 | 歩兵3対歩兵3の正面の戦いに、騎兵1を加える。騎兵を側面か背面から当てた場合は、正面から当てた場合より、勝率が高く、残る兵も多い |
| A3 | 騎兵1が盾兵1の正面に突入すると、騎兵が負ける。背面から当たると、騎兵が勝つ |
| A4 | 盾兵の後ろに置いた弓兵は、近づいてくる歩兵を削れる（弓兵なしの場合より勝率が高い）。弓兵だけで歩兵と近接すると負ける |
| A5 | 総崩れが起きる：横一列の端を崩すと、5秒以内に隣の部隊も敗走する場面が、用意した配置で8割以上の回で起きる |
| A6 | ひな形どうしの総当たり（同じ手持ち15部隊）で、決着までの長さの中央値が 40〜120秒。時間切れは全体の1割以下 |
| A7 | 同じ総当たりで、ほかのすべてに勝ち越すひな形がない。ほかのすべてに負け越すひな形もない |
| A8 | 号令が効く：用意した場面で、適切な号令を出した側は、出さない場合より勝率が高い。4回目の号令は受け付けられない |
| A9 | 本陣が全滅・敗走した刻みで決着する。本陣以外がすべて消えた刻みで決着する。時間切れの3通りが正しく判定される |
| A10 | 同じ種と同じ入力で2回動かすと、最後の状態が完全に一致する。状態を JSON にして戻してから続けても、結果が変わらない |
| A11 | 兵力が同じなら、方針を全部「守備」にした軍は、前進してくる敵に対して不利すぎない（盾と弓の守りが成り立つ）。同時に、守備だけの軍どうしは時間切れになる |

- 調整用に、戦いを文字で表示する道具（`pnpm sim`：1戦を数秒おきに文字の盤面で出す、総当たりの表を出す）を用意する。
- A6・A7 の表は、調整のたびに `docs/balance.md` に残す。

### 3.10 ステージのデータ

```ts
interface Stage {
  id: string; chapter: 1 | 2 | 3; index: number; name: string;
  hint: string;                               // 配置画面に出す1行。説明は面の作りで伝える
  field: Field;
  roster: Partial<Record<Kind, number>>;      // 手持ち。本陣は必ず1

  enemyOrders?: { atSec: number; target: OrderTarget; kind: OrderKind }[];

```

- すべての面で、`solution` が20回中18回以上勝ち、星2つ以上を取れることをテストする。
- 第1章の2面目以降は、横陣で全部隊を前進させるだけでは、20回中10回以下しか勝てないことをテストする（工夫が要る面になっている）。

| 面 | 手持ち | ねらい |

| 1-2 盾の壁 | 歩兵と盾兵 | 敵の騎兵の正面に盾を置く |
| 1-3 矢の雨 | 歩兵・盾兵・弓兵 | 盾の後ろから弓で削る。守って勝つ |
| 1-4 両翼の騎馬 | 4兵種。方針が開く | 騎兵を迂回させて、敵の側面を崩す |
| 1-5 平原の決戦 | 4兵種。号令が開く | 鶴翼の敵を、号令を使って破る |

## 4. server（段階3）

### 4.1 作り

- Worker が `/api/*` を受け、それ以外は client の静的ファイルを返す。
- 部屋1つを Durable Object 1つが受け持つ（SQLite バックエンド）。部屋のコード（4桁の数字）から `idFromName` で引く。
- WebSocket は Hibernation API（`ctx.acceptWebSocket`）で受ける。部屋が動いていない間は、Durable Object が眠れる。
- `compatibility_date` は `2026-11-01`。
- Origin の確認と、メッセージの大きさ・頻度の上限は、超富豪の server と同じ考え方で入れる。

### 4.2 通信の方式

**サーバーが engine を刻み、席ごとに見える場面を送る。** 各自の端末で同じ計算を並行して走らせる方式は採らない。理由は2つ：相手の方針を端末に送らずに済むこと、戦闘の途中で戻った人にその時点の場面を渡せば済むこと。

- 戦闘中は `setInterval`（100ms）で刻む。呼ばれるたびに「開戦からの実時間 ÷ 100ms」と、進めた刻みの数との差だけ `step` を呼ぶ（1回の呼び出しで最大5刻み）。遅れても、戦いの長さが実時間からずれない。
- 場面は2刻みごと（毎秒5回）に、席ごとに `viewFor` を通して送る。client は前後の場面のあいだを補って描く。
- 決着したら `setInterval` を止める（止めないと Durable Object が眠れない）。
- 戦闘の状態は、1秒ごと（10刻みごと）と決着時に、Durable Object の保存領域に書く。Durable Object が作り直されたら、保存した刻みから続ける。
- 配置の制限時間、公開から開戦までの間、不在の判定、部屋の片付けは、アラーム（`setAlarm`）で扱う。期限は1つにまとめ、いちばん近いものをアラームに入れる。

> Cloudflare の公式資料で確かめたこと（2026-11-16）：
> - `setInterval` が動いている間、Durable Object は眠らず、実行時間が課金の対象になる。無料プランの枠は1日 13,000 GB-秒で、128MB の Durable Object が1日に約28時間動ける計算になる。1戦は最長3分なので、友達どうしで遊ぶ量なら足りる。
> - `compatibility_date` が `2026-10-01` 以降なら、動いている `setInterval` が、接続のない間も Durable Object の追い出しを防ぐ（1つの操作につき最長15分）。
> - 受け取る WebSocket のメッセージは、20通で1リクエストと数える。送るほうは数えない。

### 4.3 部屋の流れ

```
waiting（1人）→ setup（配置。120秒）→ reveal（公開。3秒）→ battle（最長180秒）→ result → setup …
```

- 部屋を作る：`POST /api/rooms`。空いているコードが出るまで引き直す。
- 入る：`GET /api/rooms/:code/ws?pid=…&name=…`。`pid` は端末が作って保存している識別用の番号。同じ `pid` で入り直すと、同じ席に戻る。3人目は断る。
- 部屋を作った人が陣営0、入った人が陣営1。どちらの画面でも自軍が下に見えるように、client が上下を返して描く（翼の左右も、自分から見た向きで扱う）。
- `setup`：戦場を選び（段階3は平原だけ）、両者に配置を求める。client は、配置が変わるたびに下書きを送る（0.5秒に1回まで）。「完了」で確定。2人とも確定するか、期限が来たら次へ。期限の時点で下書きが検査を通らない人は、最後に通った下書きを使う。それもなければ、横陣のひな形を既定の編成で並べる。
- `reveal`：両軍の配置（方針を除く）を両者に送る。3秒後に開戦。
- `battle`：号令を受け付ける。切れている人の部隊はそのまま戦う。戻ってきた人には、その時点の場面と、残りの号令の回数を送る。
- `result`：勝敗、振り返り、通算成績を送る。両者が「もう一戦」を押すと `setup` へ。
- 決着した時点で片方が60秒以上いなければ、その席を空けて `waiting` に戻す。
- 誰もいない状態が10分続いたら、保存した内容を消す。

### 4.4 メッセージ

型は `packages/server/src/protocol.ts` に置き、client が型だけを読み込む。

| 向き | 種類 | 中身 |
|---|---|---|
| S→C | `room` | 状態、席（名前・接続中か・確定したか）、通算成績、期限の時刻、自分の陣営、戦場、予算 |
| S→C | `reveal` | 両軍の配置（相手の方針なし）、開戦の時刻 |
| S→C | `snap` | 刻み、部隊の一覧（詰めた配列）、出来事、残りの号令 |
| S→C | `result` | 勝者、理由、振り返り、通算成績 |
| S→C | `error` | 理由（部屋がない、満員、配置が不正、号令が不正） |
| C→S | `draft` | 配置の下書き |
| C→S | `ready` / `unready` | 配置の確定と取り消し |
| C→S | `order` | 相手（翼）と号令の種類 |
| C→S | `rematch` | もう一戦 |

- 配置はサーバーが `validateArmy` で検査する（自分のエリア内、重なりなし、本陣1つ、予算内、部隊数の上限）。
- 対戦の配置は、どちらの席も「自分が下」の座標で送る。サーバーが陣営1のぶんを上下左右に返して戦場の座標にする。

## 5. client

### 5.1 画面

| 画面 | 中身 |
|---|---|
| タイトル | 「ステージ」「対戦」。対戦は第1章を終えるまで選べない |
| ステージ選択 | 章と面、取った星 |
| 配置 | 戦場、手持ち（対戦は編成と予算）、ひな形、方針の切り替え、「開戦」 |
| 戦闘 | 戦場、残り時間、号令、早送り（1人用だけ） |
| 結果 | 勝敗、星、振り返り、「もう一度」「次へ」「戻る」 |
| 部屋 | 「部屋を作る」「コードで入る」、名前、相手待ち、通算成績 |

- Phaser のシーンとして作る。名前とコードの入力だけ、素の HTML の入力欄を重ねる。
- 配置の操作：手持ちの部隊を選んでマスを押すと置く。置いた部隊を引きずると動く。ほかの部隊の上に落とすと入れ替わる。置いた部隊を押すと、方針の切り替えと「外す」が出る。マウスとタッチの両方で同じに動く。
- 号令の操作：相手（全軍・左翼・中央・右翼）を押す → 号令（突撃・堅守・後退）を押す。残りの回数は3つの印で示す。相手を選んだとき、対象の部隊を光らせる。

### 5.2 戦闘を映す仕組み

```ts
interface BattleSource {
  onFrame(cb: (frame: { tick: number; view: BattleView; events: BattleEvent[] }) => void): void;
  order(target: OrderTarget, kind: OrderKind): void;
  setSpeed?(mult: 1 | 2): void;        // 1人用だけ
  dispose(): void;
}
```

- `LocalBattleSource`：ブラウザで engine を動かす。実時間をためて 0.1 秒ごとに `step` を呼ぶ（早送りは2倍ためる）。場面は2刻みごとに出す（対戦と同じ見え方にする）。
- `RemoteBattleSource`：サーバーの `snap` をそのまま流す。
- 戦闘の画面は `BattleSource` だけを見る。前の場面と今の場面のあいだを、時間で補って描く。
- 部隊の描き方は「戦場の座標 → 画面の座標」の変換を1か所（`FieldView`）に閉じ込める。段階5の斜め視点は、この変換と絵の組を差し替えて足す。

### 5.3 見た目

- ドット絵。1マス 24px。部隊は、兵数に応じた数の小さな兵（4×4px、最大16人）と、兵種を示す旗で描く。兵が減ると、描く兵も減る。
- 陣営の色は2色（自軍と敵軍）。対戦でも、自分がいつも同じ色で下にいる。
- 士気は、旗の高さで示す（下がるほど旗が下がる）。数字や棒は常には出さない。部隊を押している間だけ、兵数と士気を出す。
- 画面の内部の大きさは、縦長（スマホ）が 320 × 568 以上、横長（PC）が 640 × 400。戦場（288 × 384）は同じ大きさで描き、操作の欄を、縦長では下に、横長では右に置く。拡大は Phaser の FIT に任せる。
- 文字は DotGothic16 の 16px と 32px だけ。平らな塗り、2px 単位の枠。グラデーション・ぼかした影・光彩・角丸は使わない。
- 絵は、ドットの並びを書いたデータから、起動時にテクスチャを作る（画像ファイルを置かない）。段階1は、色のついた四角と点の仮の絵でよい。
- 音は効果音だけ。WebAudio で合成する（太鼓、ぶつかる音、敗走、勝ち負け）。音のファイルは置かない。最初の操作で音を解禁する。

### 5.4 保存

`localStorage` に、1つのキー（`jinkei-gassen/v1`）で JSON を置く：面ごとの星、名前、`pid`、保存した陣形（段階5）。読み書きは try/catch で包み、使えなくても遊べるようにする。

### 5.5 動かして確かめるための口

開発時だけ、`window.__jg` に、いまの画面・戦闘の状態・面を飛ばす操作を出す。ブラウザを自動で操作して確かめるときに使う。本番のビルドには含めない。
